# Maintaining the bounded parser port

The [customization audit](upstream-customization-audit.md) evaluates all 77 previous handwritten hunks and the mechanical adaptations, including alternatives and regression evidence.

The product is typed scripting for Jint. Full TypeScript compatibility, a public TypeScript AST, general JavaScript downleveling, and replacement of the Acornima ecosystem are separate commitments. Upstream cooperation is not required: all integration with the official AST and Jint uses public APIs.

## Provenance and ownership

The baseline is Acornima commit `b4508e06c520493d798064dc172ad472e44968ce`. Its parser, tokenizer, supporting private types and generated string matchers are imported into `Jint.TypeScript.Parsing`; public AST implementations and shared AST value types are excluded. Normalization changes namespaces/accessibility and mechanically adapts the public AST API before measuring our handwritten patch. The reproducible snapshot is stored in `eng/upstream/acornima`; owned partials are listed separately. Retain the full notices when distributing the source or package.

The selective acorn-typescript reference is commit `8956dc50370c7ee2ea97a3c903611079192b28d5`: type-mode entry, annotations, arrays/unions/intersections, function signatures, type members, tuples, aliases and interfaces. Modern tuple syntax is checked against the current Babel/TypeScript oracle instead of copying the plugin's older label restrictions. Four arrow regression cases derive from its `__test__/arrow-function/type.test.ts` (assignment pattern and issues 32, 38, 39). These are adapted algorithms and fixtures, not a translation of its extended AST or a claim to support the full plugin.

The abandoned FoundatioFx tokenizer experiment is not used as the parser baseline. Its observed negation, assertion, import-alias and location failures inform regression tests. The `as` precedence probe now preserves the addition lost by that experiment.

The handwritten upstream delta is **204 added and 82 removed lines** across five baseline files, with 900 patch lines including context. Eleven owned partials are excluded from that patch and from upstream merges. Type grammar, declaration erasure, assertions, generics, class modifiers, signatures, ambient declarations and unsupported-syntax diagnostics live in the `Parser.TypeScript.*` partials. `Parser.PublicAst.cs` owns node-list, location and regex integration; `Tokenizer.TypeScript.cs` owns type-mode state, boundary rescanning and a wrapper that preserves the lookahead string pool while calling untouched upstream reset logic. Remaining upstream edits connect those helpers and preserve public AST construction boundaries. See the [upstream update workflow](upstream-updates.md) for the exact ownership map and commands.

Unsupported declarations reuse the existing statement-list, export and ambient-declaration hooks. Supported ambient declarations reuse their existing lookahead instead of scanning a second time. Constructor parameter-property diagnostics require one check before binding parsing: accessibility words otherwise fail the upstream reserved-word check before our annotation helper runs. A constructor flag passes through the existing class-method and parameter-list entry points, so ordinary methods, nested functions and parameters named `readonly` retain their native behavior. Diagnostic matching, messages and original positions stay in the owned `Parser.TypeScript.Diagnostics.cs` partial; no upstream error-reporting methods were copied or rewritten.

Assertions enter the binary precedence loop at relational precedence; postfix non-null enters the subscript loop without closing an optional chain. A lazy set of existing nodes preserves assertion information until parameter-binding reinterpretation is complete. Boundary operators are rescanned when leaving type mode. Template substitutions consume type grammar directly without constructing literal/type nodes. Mapped types use bounded lookahead, with a fast path for ordinary property shapes.

Conditional types pass an explicit context flag through union/intersection operands and function returns. The outer `extends` operand suppresses an unparenthesized conditional; nested parentheses, arguments and members restore ordinary type grammar. Infer constraints consume their shared prefix once without speculative rollback or a type AST. Const/variance modifiers reuse the type-parameter parser; the existing class hook supplies `allowVariance: true`. Import types and import queries consume strings and qualified names without creating module dependencies.

Class erasure passes abstract context through class/member parsing as arguments, so nested classes cannot inherit it accidentally. Abstract signatures use the existing native binding parser and overload-erasure path; owned helpers reject bodies and validate accessor arity before temporary nodes are discarded. Ordinary erased field names use a bounded lookahead and shared modifier/name checks without building identifier nodes. Computed, private, quoted and contextual-keyword names retain native parsing. Remaining temporary computed-key and signature nodes count against node budgets. Concrete class fields keep native define semantics. The [class-erasure validation](class-erasure-validation.md) explains each added hook and its alternatives.

Declaration erasure occurs only in statement lists, not single-statement if/loop bodies. Type names do not enter JavaScript scopes. Ordinary function heads are parsed once; a missing body erases a permitted overload after validating parameters and leaving its temporary function scope. Runtime declaration bindings are registered only after parsing an implementation. Nullable results are consumed only by statement lists, export wrappers and class bodies; required statements still reject erasure. Erased signatures do not terminate the emitted directive prologue. Temporary runtime parameter/key nodes remain counted against the node budget. Ordinary ambient variable declarations create no binding nodes; their types and repeated names have constant allocation cost. Non-abstract bodyless accessors are excluded because TypeScript emits executable accessors for them. Explicit whole type-only module declarations disappear; inline specifiers retain their containing module declaration for side effects. An EOF-positioned empty export preserves a wholly erased module when serialized. Keep contextual names such as `type`, `as` and `from` covered by both reference and negative tests.

Public node constructors run before their range/location initializers, preserving end positions when a constructor argument itself parses children. Literal leaves use their current token end and retain upstream construction-before-Next order. Variable declarations retain lightweight construction parts until the terminating punctuation is consumed. Public `NodeList.From` copies node references once; there is no second program AST. This is a deliberate allocation cost, measured in the benchmark.

The imported source is about 20,000 C# lines including helpers and generated code. Owning a small delta still requires reviewing upstream JavaScript fixes and Acornima/Jint API changes. Untouched inherited regex-conversion helpers are retained to avoid widening the fork patch; the production adapter delegates regex validation and Jint metadata to the official tokenizer.

## Reconstruct and verify the baseline

Run `node eng/upstream.mjs check` for an offline, byte-for-byte reconstruction check. After an intentional parser edit, run `node eng/upstream.mjs refresh`. To independently regenerate the pinned baseline, run `node eng/upstream.mjs verify-origin --work-dir artifacts/acornima-origin-check` with a new output directory.

The [upstream update workflow](upstream-updates.md) documents staged three-way merges, conflict resolution, provenance checks, backup/rollback and the `$jint-update-acornima` skill. The importer and Roslyn adapter are mechanical; TypeScript grammar stays in owned partials and small upstream hooks. Maintenance uses Node, C# and Git, with no Python or runtime JavaScript parser.

## Upgrade policy

1. Refresh source and package metadata, record the exact selected revisions, and review upstream parser/Jint preparation changes. Preview packages may disappear from a rolling feed; advance pins deliberately instead of restoring an unspecified latest version.
2. Generate a new normalized baseline in staging, apply/reconcile the owned patch, and inspect any new node-finalization or collection-construction sites. Never copy official AST types into this assembly or access their internals by reflection/unsafe setters.
3. Update the package references, lockfiles and `eng/upstream.json` together. Verify regex metadata with static analysis enabled and disabled, original diagnostics, prepared modules, and AST identity.
4. Run the JavaScript compatibility corpus and focused tests. Regenerate JavaScript fixtures from the new baseline with `eng/ImportFixtures` and review every acceptance change. Do not automatically regenerate expectations to make failures disappear.
5. Regenerate TypeScript reference fixtures when syntax support or reference compiler versions change, then compare ASTs and execution. Run the release benchmark and investigate timing/allocation regressions before broadening support.

The JavaScript corpus selects 951 fixtures accepted in script or module mode by Acornima 1.8.0; it excludes third-party bundles and JSX. The 663 candidates rejected by official Acornima are retained: 662 must still fail in both modes, while `class A {a:0}` is now explicitly tested as a valid TypeScript field annotation. Pass a third output path to `eng/ImportFixtures` to regenerate that negative corpus. This is a baseline regression corpus, not all Test262 or all Acornima tests.

Regenerate reference fixtures with `npm ci --ignore-scripts` and `npm run generate` in `eng/reference-checks`. Babel 8.0.4 validates selected sources (one explicitly marked async-arrow predicate is checked by TypeScript alone because Babel rejects it); TypeScript 7.0.2 emits ESNext JavaScript with `noCheck` and `verbatimModuleSyntax`. `hardening-cases.mjs` adds seeded nested types across 20 contexts; `milestone-cases.mjs` adds richer compositions and declaration/module fixtures; `parity-cases.mjs` adds assertions, generic functions and mapped/template types; `generics-cases.mjs` adds generic expressions/arrows/methods/classes, class modifiers/fields and comparison ambiguity. `signature-cases.mjs` adds readonly/query types, predicates, receiver parameters, overloads and selected ambient declarations. `type-syntax-cases.mjs` adds conditional/infer types, const/variance parameters and import types; `class-erasure-cases.mjs` adds abstract classes/members, declare fields and abstract constructor types. Each contributes Babel-filtered mutations, with an exact exclusion for that separately verified Babel limitation. The negative oracle disables top-level return to match Babel. No type-checking claim follows from those tests. Explicit strict directives align script semantics with TypeScript 7, which no longer supports `alwaysStrict=false`. Committed JSON fixtures let ordinary .NET builds run without those development tools; CI independently checks reproducible regeneration.

Run the isolated stress executable on both runtimes as well as the unit suite. Each child gets a 20-second timeout; a native crash or unexpected exception fails the runner. Keep performance checks in two layers: deterministic allocation/token-budget checks in unit tests, and release measurements for timing. Long comparisons and erased declarations must fit linear token budgets; repeated unions, readonly type members, tuples and pure type signatures must not allocate per erased member. Runtime-shaped overload heads construct temporary binding/key nodes and therefore allocate with their count; benchmark those separately. Ordinary ambient variable names take a path that creates no nodes. Escaped/reserved/context-sensitive names retain the native identifier checks. Lookahead retains its string deduplication table within one parse; the parser and probe are discarded after that parse. There is no cross-parse parser-state pool. Only the preparation-depth traversal buffer is pooled across calls and it is cleared before return.

## Subsequent scope

The experiment's 57-test parity snapshot is exceeded by the current syntax support, now including abstract classes/members, declare fields and abstract constructor types. The [hosting sample](../samples/Jint.TypeScript.Sample/README.md) demonstrates file loading and execution; preview delivery remains a product milestone. Ambient classes and declaration-only module/global blocks need separate scope/context work; non-abstract accessor signatures require a runtime-output decision. Add each production with reference, ambiguity, rejection and resource tests. Runtime enums, namespaces and constructor parameter properties need separate emission/semantics decisions. JSX, decorators, type checking and JavaScript downleveling remain outside the native erasure approach. The [experiment parity assessment](experiment-parity.md) records the remaining scope.

Execution safety remains a host responsibility: parsing limits bound compiler work, while Jint execution constraints bound script execution. Keep source mode, compiler options and dependency versions in any host cache key.
