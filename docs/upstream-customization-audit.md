# Audit of upstream customizations

Reviewed every one of the **77 hunks** in the [pre-audit handwritten patch](audits/customization-audit-before.patch), plus the mechanical import/normalization rules and owned bridge alternatives. The [structured audit](upstream-customization-audit.json) maps each original hunk to its upstream file/line and one of the decisions below. Hunk IDs are a historical snapshot, not stable identifiers for future patches.

The previous patch reduction separated owned helpers and automated adaptations. **Automated adaptation is still a modification to upstream code.** The goal of this audit is to remove unnecessary changes and reduce ownership of upstream behavior, not merely make the handwritten patch look smaller. Decisions marked Keep mean necessary for the current supported behavior, public-AST boundary and performance goals; they are not a claim that no other architecture could work.

## Implemented result

The handwritten patch falls from **972 to 842 lines**, and from **233 added / 95 removed** to **185 added / 77 removed** lines. Five upstream files retain manual changes instead of six. Ten owned partials remain; 69 of 74 imported files now match the mechanically normalized baseline exactly. This is a comparison against normalized upstream, not a claim that those files are raw upstream bytes.

The tokenizer reset override is gone; its owned wrapper preserves the string pool without copying reset logic. Literal dispatch and construction order now follow upstream, with current-token location initializers. Class checks and inline module-specifier erasure use owned helpers. Unsupported decorator rewriting and formatting/qualification differences were removed. Two existing public node-list substitutions moved into mechanical normalization; those are reported as automation, not removed behavior.

Locked restore and Release build passed with zero warnings/errors. **18,903 tests pass on each native runtime (.NET 8.0.30 and .NET 10.0.11)**, including 16 new tests for literal/import-attribute boundaries, long-name lookahead allocations and source recovery, distinct-regex allocation budgets, and decorator rejection in both source modes. **38 isolated stress cases per runtime**, all **57 original experiment tests**, and a fresh-cache packaged consumer pass. All **31 maintenance tests** pass; pinned-baseline restaging and fresh origin reconstruction also pass. The package/source dependency pins are unchanged, and hosted CI has not run.

## Mechanical transformations and larger alternatives

| Transformation | Assessment | Alternatives and maintenance consequence |
| --- | --- | --- |
| Select parser/tokenizer/support files; exclude official AST/shared value implementations | Keep | Shipping our own AST produces different .NET type identities from Jint's expected official assembly. Copying all upstream code would broaden ownership without satisfying that contract. |
| Private namespace, internal visibility and shared-type aliases | Keep | Compiling the fork in the official namespace creates type ambiguity; exposing parser implementation classes makes them a second public API. Existing import normalization is deterministic. Comment/qualification changes made by normalization are not runtime features. |
| Generated string-matcher snapshots | Keep | Building the upstream generator at a frozen commit is reproducible; running a second generator on all owned partials complicates build ownership and consumers. Generated files carry no handwritten customizations. |
| BOM/newline normalization | Keep | Canonical LF and .gitattributes avoid platform-only hash/merge differences. These changes do not alter parser behavior. |
| Range/Position/SourceLocation/TemplateValue constructors to public factories | Keep | Constructors are internal to the official assembly. Reflection or parallel value types either break the contract or increase fragility. Qualified template factory noise in handwritten code was removed. |
| Node field reads to public Range/Location | Keep | Accessing official internal fields is unavailable; public properties preserve values. Moving this into manual per-site patches would increase repeated work. |
| Direct node-finalization arguments get public init-only locations | Keep | Initialize after constructor arguments finish parsing children. Closure factories allocate, postpasses copy/walk nodes, and internal setters are unavailable. Literal tokens can instead initialize before Next; their smaller explicit boundary adaptation remains in the handwritten patch. |
| NodeList.From(ref private ArrayList) to owned public bridge | Keep | The bridge uses official From and resets the source list. The public API copies references once and may box the private value-type collection. Zero-copy constructors require official assembly internals. An array/iterator intermediate adds work. |
| One-argument NodeList constructors to public From | Automate | Two existing handwritten substitutions now use the same normalization rule. This removes manual merge work, not their public-factory copying cost. Array/count ownership constructors are deliberately excluded and still require review. |
| Official tokenizer for regular-expression leaf metadata | Keep, simplify raw text reuse | Jint expects metadata created with its published parsing options. Our private regex structures are different types. Pass the already-read raw text to the public tokenizer, retaining the previous substring policy so distinct patterns do not grow the identifier pool. Delegating the complete tokenizer would lose native TypeScript grammar hooks. |
| Retain unchanged upstream helpers, including unused regex conversion branches | Keep unchanged | Deleting inherited code adds a large deletion delta and can break later upstream internal dependencies. Keeping it byte-identical after normalization is cheaper to merge. This is not a new supported runtime feature. |
| Move whole upstream methods into partial files | Reject as a general strategy | It makes the patch smaller while silently taking ownership of future upstream bug fixes. Extract TypeScript-only blocks; retain native method bodies and integration points. |
| Replace hooks with callbacks or parser-wide mutable mode fields | Reject for current implementation | Per-token/per-node delegates introduce cost and different accounting. Shared mutable modes need nesting/exception restoration. Small direct hooks and explicit arguments keep performance and context visible. |
| Official parser extension/subclass instead of a parser subset | Not currently sufficient | The required grammar/tokenizer internals are not a public extensibility contract in the pinned source. Reconsider if upstream publishes suitable hooks; do not fork Jint or move parsing into a JavaScript engine. |

## Performance and the rejected regex alternative

The [final control](benchmarks-customization-audit-final-control.json) uses the saved pre-audit parser. The [final implementation](benchmarks-customization-audit-final.json) uses the audited source. Both run the same expanded benchmark code, sequentially after other checks finish, on .NET 10.0.11 with tiered compilation disabled. **All 102 workload/size combinations allocate exactly the same number of bytes.** Representative 1,000-item results:

| Workload | Control | Final | Timing difference | Allocated bytes, both |
| --- | ---: | ---: | ---: | ---: |
| Owned JS parse | 1.931 ms | 1.986 ms | +2.9% | 2,357,808 |
| Owned TS parse | 2.302 ms | 2.314 ms | +0.5% | 2,357,848 |
| Owned TS prepare | 4.274 ms | 4.291 ms | +0.4% | 4,021,224 |
| Owned JS regex | 1.582 ms | 1.609 ms | +1.7% | 822,648 |
| Owned JS unique regex | 1.690 ms | 1.724 ms | +2.0% | 957,048 |
| Owned TS generic calls | 0.649 ms | 0.660 ms | +1.7% | 493,384 |
| Owned TS generic classes | 2.913 ms | 2.893 ms | -0.7% | 1,830,896 |

These are shared-machine microbenchmarks. Typed parsing/preparation are within 0.6%; the table ranges from about -0.7% to +2.9%. The unchanged official JS parse/prepare controls moved about +0.0%/+0.8%. A reverse-order check of the earlier candidate changed its ordinary-JS result from a 3.7% slowdown to a 1.0% improvement. The measurements support similar representative throughput, not proof of zero overhead or a speedup.

The first literal-flow simplification inherited upstream pooling of raw regex strings. It reduced allocation for repeated patterns but increased the 1,000-distinct-pattern case from **957,048 to 1,029,040 bytes** (about 7.5%). That tradeoff was rejected. The final implementation retains the previous raw substring policy, and the benchmark now includes both repeated and distinct patterns. Two allocation-budget tests prevent reintroducing the distinct-pattern cost. This small explicit deviation from upstream is justified by measured behavior rather than patch size.

Earlier candidate measurements are retained in the other customization-audit JSON files and labeled where superseded; they are not the final implementation's allocation results.

## Future changes

Read this audit when updating upstream. Compare every changed handwritten hunk and every changed normalization rule with its actual need. Restore an upstream implementation when an owned boundary wrapper can preserve behavior without extra parsing, AST copies or unsafe state. Do not move a whole upstream method or add a source-pattern rewrite solely to reduce the patch count. Add new decisions when behavior or the tradeoff changes, and verify locations, invalid contexts, budgets and allocation costs.
